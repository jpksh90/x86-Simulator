# Test binaries

These fixtures are built once and committed, so the tests need no compiler, assembler or linker.
`ListingGoldenTest` compares the disassembly of each one with its `<name>.expected.asm`. Each
expected listing was generated by the implementation and then checked by hand against
`objdump -d --x86-asm-syntax=intel <file>` (macOS's LLVM objdump): every address, byte, mnemonic
and operand matches, differing only in label names and number style.

| File | Source | Built with (macOS, Apple clang) |
|------|--------|---------------------------------|
| `hello-macho` | `src/hello.c` | `clang -arch x86_64 -O1 -o hello-macho src/hello.c && strip -x hello-macho` |
| `hello-elf.o` | `src/hello-elf.s` (the `01_hello` example in GNU Intel syntax) | `clang -target x86_64-linux-gnu -c src/hello-elf.s -o hello-elf.o` |
| `hello-pe.exe` (not a file) | `TestBinaries.helloPe()` | built in memory by the test builders |

No Linux linker or Windows toolchain was available when these were made (Docker was not running),
so the ELF fixture is a relocatable object file rather than a linked executable, and the PE fixture
is synthetic. `objdump` reads the synthetic PE and agrees with its listing. Linked ELF executables
are covered by the synthetic images in `TestBinaries.elf64`.

To add a linked ELF and a real MinGW PE later (e.g. in a Debian container):

```sh
nasm -f elf64 ../../../main/resources/examples/01_hello.asm -o hello.o && ld -s hello.o -o hello-elf
x86_64-w64-mingw32-gcc -O1 -s -nostdlib -e main hello-pe.c -lkernel32 -o hello-pe.exe
```
